# Предложения по улучшению (не дефекты ТЗ)

Эти наблюдения **не** оформлены как баги: на них нет прямого пункта требований 1–22.

1. **Зеркальная операция при internal-переводе.** Проверено: `acc-1 → acc-2` на `50` — баланс источника −50, получателя +50, но в `GET /api/transactions` новая запись только у источника (`direction: out`, `accountId: acc-1`); у `acc-2` `total` не меняется, зачисления `in` нет. В handlers создаётся одна транзакция на `from`. В ТЗ требования зеркальной проводки нет — improvement для сверки выписки получателя.
2. **Статусы в админке** показываются сырыми (`pending` / `done` / `failed`), тогда как в истории клиента — локализованные бейджи. Единообразие UI.
3. **Валидация получателя во внешнем переводе.** В ТЗ нет формата карты/телефона. Сейчас API отбрасывает нецифры и отклоняет только если цифр < 10; UI — обычный `text` + `required`. В итоге буквы и "мусор" с ≥10 цифрами проходят, короткий телефон — нет, без проверки маски/длины карты. Имеет смысл явные правила (маска, длина, только цифры) на UI и на API.
